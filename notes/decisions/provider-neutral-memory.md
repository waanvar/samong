# ความจำต้องไม่ขึ้นกับค่าย AI (provider-neutral memory)

**บริบท** คำถามของเจ้าของโปรเจกต์: ถ้า Samong จะจำแทนคน ต้องบันทึกอะไรไว้ให้งาน
ไม่เพี้ยน ไม่ว่าจะผ่านไปนานแค่ไหน หรือเปลี่ยนค่าย AI ไปกี่ครั้ง ตัวอย่างที่ยกมา:
ปิด feature A แล้ว ผ่านไปสักพักเปลี่ยนไปใช้ AI อีกค่ายมาทำ feature B

**สิ่งที่พบในโค้ด (ก่อน PR #9)**
1. วงจร "ค้นก่อน บันทึกหลัง" อยู่ใน `CLAUDE.md` อย่างเดียว ซึ่งมีแค่ Claude ที่อ่าน
2. `initialize` ของ MCP (`src/mcp.rs`) ไม่ส่ง `instructions` agent ที่ต่อเข้ามาไม่ได้
   รับคำบอกอะไรเลยว่าควรใช้โน้ตอย่างไร
3. โน้ตไม่มีวันที่ สถานะ หรือการบอกว่าอะไรแทนอะไร ผลค้นแยกการตัดสินใจล่าสุดกับ
   ที่ถูกยกเลิกไม่ออก

**ที่เลือก (PR #9)**
- ส่งวงจรในช่อง `instructions` ของ MCP — ไคลเอนต์ที่รองรับส่งให้โมเดลเองโดยไม่ขึ้น
  กับค่าย ข้อความเขียนให้ใช้ได้กับ vault ไหนก็ได้ จำกัด 2,000 ไบต์
- `AGENTS.md` เป็นสำเนาเดียวของคำสั่ง `CLAUDE.md` แค่ `@AGENTS.md`
- template โน้ต START / decision / handoff ใน `docs/AI-AGENT.md`
- สองทางแรกเสริมกัน ไม่ได้แทนกัน: ไคลเอนต์ที่ไม่อ่าน `instructions` จะไม่เห็นมัน
  และไม่มีอะไรบอก

**ทางที่ไม่เลือก** คัดลอกคำสั่งไว้ทั้ง `CLAUDE.md`, `AGENTS.md`, `GEMINI.md` —
ง่ายกว่าแต่เป็นสามสำเนาที่ต้องแก้ให้ตรงกันด้วยมือ โปรเจกต์นี้เคยพลาดแบบนี้แล้วกับ
เลข MSRV ที่เขียนไว้หลายที่

**ห้ามพัง** และเทสต์ที่ป้องกัน
- `CLAUDE.md` ต้อง import `@AGENTS.md` และไม่มีหัวข้อของตัวเอง →
  `tests/msrv.rs` `claude_md_imports_the_shared_instructions_and_adds_none_of_its_own`
- `AGENTS.md` ต้องบอกเลข Rust ที่ตรงกับ `Cargo.toml` (และต้องมีเลข) →
  `tests/msrv.rs` `the_agent_instructions_state_the_msrv_that_cargo_enforces`
- `instructions` ต้องถูกส่ง สั้น และเอ่ยถึงเฉพาะ tool ที่มีจริง →
  `src/mcp.rs` tests `initialize_tells_every_client_how_to_use_the_notes`,
  `instructions_stay_short`, `every_tool_the_instructions_name_exists`

**ไฟล์ที่เกี่ยว** `src/mcp.rs`, `AGENTS.md`, `CLAUDE.md`, `docs/AI-AGENT.md`,
`tests/msrv.rs`

## บทวิเคราะห์ 10 เคส

แต่ละเคส: ต้องบันทึกอะไร · ขาดอะไร (ณ 2026-11-05)

1. **ปิด feature A แล้วเปลี่ยนค่าย AI มาทำ feature B** · โน้ตการตัดสินใจของ A
   (เหตุผล ทางที่ไม่เลือก สิ่งที่ห้ามพังพร้อมเทสต์) · *ปิดแล้วใน PR #9*
2. **เพิ่มหน้าจอหลัง production นาน** · `docs/DESIGN.md` · *ปิดแล้วใน PR #8 + #9*
3. **เคยตัดสินใจ X แล้วเปลี่ยนเป็น Y** · โน้ตเดิมต้องบอกว่าถูกแทนและชี้ไปโน้ตใหม่ ·
   template มีแล้ว แต่ผลค้นยังไม่ติดป้าย → [[next-features]] ข้อ 1
4. **บั๊กที่แก้แล้วมีกับดักเฉพาะจุด** · โน้ตที่ระบุ path ของไฟล์และเทสต์ ·
   template บังคับใส่ path แล้ว
5. **ศัพท์เฉพาะธุรกิจ** · glossary ไทย+อังกฤษ · ค้นข้ามภาษาไม่เจอ คำที่ตั้งเองตัด
   ไม่ถูก → `claude/user-dictionary` ([[unmerged-branches]])
6. **เปลี่ยน AI กลางคันขณะงานยังไม่เสร็จ** · โน้ตส่งต่องาน · *template มีแล้ว และ
   `instructions` สั่งให้เขียน*
7. **deploy / release / environment** · runbook ที่บอกว่า secret อยู่ที่ไหน ไม่ใช่ค่า ·
   `instructions` สั่งห้าม แต่ยังไม่มีการกัน → [[next-features]] ข้อ 3
8. **ความรู้ระดับบริษัทอยู่คนละ vault** · โน้ต START ของแต่ละ vault ·
   `search_notes` คืน 8 ผลรวมทุก vault ของสำคัญอาจถูกเบียด — START ช่วยได้บางส่วน
9. **AI สองค่ายบันทึกเรื่องเดียวกันขัดกัน** · โน้ตใหม่ต้องลิงก์ถึงโน้ตเดิม ·
   `base_hash` กันเขียนทับแล้ว แต่กันโน้ตขัดกันไม่ได้ ทางที่ดีที่สุดคือโน้ตผ่าน PR
10. **โค้ดเปลี่ยน โน้ตไม่ได้แก้ตาม** · โน้ตสำคัญควรมีเทสต์ผูก (แบบ
    `tests/design_system.rs`) · → [[next-features]] ข้อ 2

## สิ่งที่ต้องบันทึกเสมอ

วงจรการทำงานในที่ที่ทุกค่ายเห็น · การตัดสินใจพร้อมเหตุผลและสถานะ · สิ่งที่ห้ามพัง

runbook ที่ไม่มีค่า secret · START ของแต่ละ vault
