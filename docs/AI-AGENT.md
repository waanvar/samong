# ใช้ Samong เป็นมันสมองของ AI agent 🧠

Samong ถูกออกแบบให้เป็น "ความจำถาวร" ของ AI coding agent — agent ค้นความรู้เก่า
ก่อนทำงาน แล้วบันทึกสิ่งที่เรียนรู้ใหม่กลับเข้า vault วนเป็นวงจร

## ทางที่ 1: MCP (แนะนำ)

`samong-mcp` เป็น MCP server บน stdio — เครื่องมือที่รองรับ MCP จะเห็น Samong เป็น
tools ในตัว

### อ่านสองบรรทัดนี้ก่อน จะประหยัดเวลามาก

**MCP เป็นความสามารถของ "ไคลเอนต์" ไม่ใช่ของ "โมเดล"** — คำถามที่ถูกไม่ใช่
"GPT ต่อ MCP ได้ไหม" แต่คือ "โปรแกรมที่ผมใช้คุยกับ GPT ต่อ MCP ได้ไหม" โมเดล
เดียวกันจึงต่อได้หรือไม่ได้ ขึ้นกับว่าคุณเรียกใช้มันผ่านอะไร

**`samong-mcp` รันบนเครื่องคุณผ่าน stdio** ⇒ ต่อได้เฉพาะไคลเอนต์ที่รันบนเครื่อง
เดียวกัน · **แอปบนเว็บล้วนๆ ต่อไม่ได้** (ChatGPT บนเว็บ, Gemini บนเว็บ, Grok ใน X)
เพราะมันอยู่บนเซิร์ฟเวอร์ของเขา ไปเรียกโปรเซสในเครื่องคุณไม่ได้ ตัวเชื่อมแบบ
connector ของพวกนั้นต้องการ MCP server ที่เป็น URL สาธารณะ ซึ่งขัดกับสิ่งที่
Samong เป็น — โน้ตไม่ออกจากเครื่อง

### ตารางสรุป

| ไคลเอนต์ | โมเดล | คำสั่งเพิ่ม | ไฟล์ตั้งค่า |
|---|---|---|---|
| Claude Code | Claude | `claude mcp add --scope user samong -- samong-mcp` | `.mcp.json` |
| Claude Desktop | Claude | ติดตั้งไฟล์ `.mcpb` จากหน้า release | `claude_desktop_config.json` |
| Codex CLI / ChatGPT desktop | GPT | `codex mcp add samong -- samong-mcp` | `~/.codex/config.toml` |
| Gemini CLI | Gemini | `gemini mcp add samong samong-mcp` | `~/.gemini/settings.json` |
| Qwen Code | Qwen | `qwen mcp add samong samong-mcp` | `~/.qwen/settings.json` |
| Kimi Code CLI | Kimi | `kimi mcp add samong -- samong-mcp` | จัดการผ่าน `kimi mcp` |
| Grok Build | Grok | `grok mcp add samong -- samong-mcp` | `~/.grok/config.toml` |
| GLM (Z.ai) | GLM | ใช้ผ่านไคลเอนต์อื่น — ดูด้านล่าง | ของไคลเอนต์นั้น |
| DeepSeek | DeepSeek | ใช้ผ่านไคลเอนต์อื่น — ดูด้านล่าง | ของไคลเอนต์นั้น |

> ถ้ายังไม่ได้ `cargo install` ให้ใส่ path เต็มของไบนารีแทนคำว่า `samong-mcp` เช่น
> `C:\path\to\samong\target\release\samong-mcp.exe`

### รูปแบบไฟล์ตั้งค่า

ไคลเอนต์ตระกูล JSON — **Claude Code, Gemini CLI, Qwen Code** ใช้โครงเดียวกันเป๊ะ
ต่างกันแค่ที่อยู่ของไฟล์:

```json
{
  "mcpServers": {
    "samong": { "command": "samong-mcp" }
  }
}
```

ไคลเอนต์ตระกูล TOML — **Codex CLI และ Grok Build**:

```toml
[mcp_servers.samong]
command = "samong-mcp"
```

> Codex ใช้คีย์ `mcp_servers` (ขีดล่าง) ไม่ใช่ `mcpServers` แบบ JSON — ตัวสะกดนี้
> พลาดกันบ่อยและมันจะเงียบ ไม่ฟ้องว่าตั้งค่าผิด

### GLM, DeepSeek และโมเดลที่ไม่มีไคลเอนต์ของตัวเอง

สองตัวนี้เป็น **โมเดล** ไม่ใช่ไคลเอนต์ MCP — คุณเรียกใช้มันผ่านโปรแกรมอื่น และ
**การตั้งค่า MCP เป็นของโปรแกรมนั้น ไม่ใช่ของโมเดล**

- **GLM Coding Plan ของ Z.ai** ออกแบบมาให้เสียบเข้ากับไคลเอนต์ที่มีอยู่แล้ว เช่น
  Claude Code, Cline, OpenCode ⇒ ตั้ง Samong ตามไคลเอนต์นั้นตามปกติ แล้ว GLM จะ
  เห็น tools ของ Samong เหมือนกัน
- **DeepSeek** ไม่มี CLI ของตัวเองที่เป็น MCP client ⇒ ใช้ผ่านไคลเอนต์ที่ตั้ง
  โมเดลเองได้และรองรับ MCP เช่น Cline, Continue, OpenCode, Zed

หลักเดียวกันใช้กับโมเดลอื่นๆ ที่ยังไม่มีในตาราง: **หาไคลเอนต์ที่รองรับ MCP ก่อน
แล้วค่อยเลือกโมเดล**

### ตรวจว่าต่อติดจริง

อย่าเชื่อว่าตั้งค่าแล้วแปลว่าใช้ได้ — ถามมันตรงๆ:

```
list_vaults ของ samong คืนอะไรบ้าง
```

ถ้าไคลเอนต์ตอบเป็นรายชื่อ vault แปลว่าต่อติด ถ้าบอกว่าไม่รู้จัก tool นี้ แปลว่า
ยังไม่ติด — ส่วนใหญ่เพราะ `samong-mcp` ไม่ได้อยู่ใน `PATH` ของโปรเซสที่ไคลเอนต์
รันขึ้นมา ซึ่งมักไม่ใช่ `PATH` เดียวกับเทอร์มินัลของคุณ ใส่ path เต็มแล้วหายไป

### Tools ที่ agent ได้

| Tool | หน้าที่ |
|---|---|
| `list_vaults` | รายชื่อ vault ทั้งหมด |
| `list_notes` | รายชื่อโน้ตใน vault เป็น **path** (มี `[reference]` ต่อท้ายถ้าเป็นโน้ตอ่านอย่างเดียว) |
| `read_note` | อ่านเนื้อหา markdown — อ้างด้วย **path** เช่น `docs/API.md` |
| `save_note` | สร้าง/แก้โน้ต (ใส่ `[[ลิงก์]]` เชื่อมความรู้ได้); ปฏิเสธถ้าเป็น reference note จาก `scope.include` เพราะไฟล์เป็นของ dependency เขียนไปก็หายตอน install ใหม่ |
| `search_notes` | ค้น full-text — ภาษาไทยตัดคำให้ ค้นกลางประโยคเจอ; `limit` คุมจำนวนผล (default 8 = ประหยัด token, **นับรวมทุก vault** ไม่ใช่ต่อ vault) |
| `get_links` | ดูความเชื่อมโยงของโน้ต (forward/backlinks/ข้าม vault) — อ้างด้วย path |

> **โน้ตอ้างด้วย path ไม่ใช่ title** เพราะ vault เดียวมีไฟล์ชื่อ `README.md` ได้หลายไฟล์
> ให้เอา path จาก `list_notes` หรือ `search_notes` มาใช้ต่อ อย่าเดาเอง

**ตั้งใจไม่มี tool ลบโน้ต** — มันสมองของ agent ควรสะสมความรู้ ไม่ควรลบเองได้
การลบเป็นเรื่องของมนุษย์ผ่าน CLI หรือ Web UI

## ทางที่ 2: CLI (ไม่ต้องตั้งค่าอะไร)

Agent ที่รันคำสั่ง shell ได้ ใช้ Samong ได้ทันที:

```sh
samong search --all-vaults "jwt refresh token"   # ค้นก่อนเริ่มงาน
samong new "บทเรียน: redb lock"                   # บันทึกความรู้ใหม่
samong links "สถาปัตยกรรม auth"                   # ดูความเชื่อมโยง
```

## สิ่งที่ agent ได้รู้ทันทีที่ต่อ

`samong-mcp` ส่งคำแนะนำการใช้งานมาตั้งแต่ตอนเชื่อมต่อ ผ่านช่อง `instructions`
ของ MCP: ค้นก่อนเริ่มงาน, อ่านโน้ต START ถ้ามี, ทำตามโน้ตการตัดสินใจ, บันทึกการ
ตัดสินใจและโน้ตส่งต่องาน, ห้ามใส่ค่า secret ในโน้ต ข้อความเต็มอยู่ที่ `INSTRUCTIONS`
ใน `src/mcp.rs`

ช่องนี้ไม่ผูกกับค่ายของโมเดล ไคลเอนต์ที่รองรับจะส่งให้โมเดลเอง ส่วนไคลเอนต์ที่ไม่
รองรับจะไม่เห็นมันเลย และไม่มีอะไรบอกคุณ — จึงยังต้องมีไฟล์คำสั่งของโปรเจกต์ตาม
recipe ด้านล่างด้วย สองทางนี้เสริมกัน ไม่ได้แทนกัน

## Recipe: วางวงจรความรู้ใน AGENTS.md

คำสั่งของโปรเจกต์ควรมี **สำเนาเดียว** ที่ AI ทุกค่ายอ่าน ถ้าเขียนไว้ใน `CLAUDE.md`
อย่างเดียว วันที่เปลี่ยนไปใช้ค่ายอื่นทำ feature ถัดไป agent ตัวใหม่จะต่อ Samong ได้
แต่ไม่รู้ว่าควรเปิดดูมัน และถ้าคัดลอกไปไว้หลายไฟล์ สำเนาจะค่อยๆ ไม่ตรงกัน

| ไคลเอนต์ | อ่านไฟล์ไหน | ทำอย่างไร |
|---|---|---|
| Codex CLI, Cursor, GitHub Copilot และอีกหลายตัว | `AGENTS.md` | เขียนคำสั่งทั้งหมดที่นี่ |
| Claude Code | `CLAUDE.md` | ใส่บรรทัดเดียว `@AGENTS.md` (Claude Code import ไฟล์ด้วย `@path`) |
| Gemini CLI | `GEMINI.md` เป็นค่าเริ่มต้น | ตั้ง `contextFileName` ใน `settings.json` ให้เป็น `AGENTS.md` |

ไคลเอนต์เปลี่ยนเรื่องนี้บ่อย ตรวจกับเอกสารของไคลเอนต์ที่คุณใช้อีกครั้ง repo นี้ใช้วิธี
นี้เอง: `AGENTS.md` เป็นสำเนาเดียว `CLAUDE.md` import มัน และ `tests/msrv.rs`
ล้มถ้าบรรทัด import หายไป

คัดลอกบล็อกนี้ลง `AGENTS.md` ของโปรเจกต์คุณ (ปรับชื่อ vault ตามจริง):

```markdown
## Knowledge base (Samong)

ความจำของโปรเจกต์นี้อยู่ใน Samong vault ชื่อ `my-project` มันอยู่นานกว่า session,
โมเดล หรือค่าย AI ใดๆ — ถือว่ามันคือสิ่งที่คนก่อนหน้าตัดสินใจไว้

**ก่อนเริ่มงาน**
- อ่าน `START.md` ของ vault ก่อน
- `search_notes` ด้วยหัวข้องาน และด้วย path ของไฟล์ที่จะแก้ ผลคือ `vault/path`
  ส่งให้ `read_note` ตรงๆ อย่าเดา path เอง
- อ่านโน้ตการตัดสินใจของส่วนนั้น และอย่าทำสิ่งที่โน้ตบอกว่าห้ามพัง
  ถ้าโน้ตบอกว่าถูกแทนแล้ว (`status: superseded`) ให้ตามไปที่ `superseded_by`
- ก่อนสร้างหรือแก้หน้าจอ อ่านโน้ตดีไซน์ของโปรเจกต์ก่อน

**ระหว่างทำและก่อนหยุด**
- ตัดสินใจสำคัญหรือแก้ปัญหายากได้ → `save_note` โน้ตการตัดสินใจ ตาม template
- งานยังไม่เสร็จตอนหยุด → `save_note` โน้ตส่งต่องาน ตาม template
- แก้โน้ตเดิมต้อง `read_note` ก่อนเสมอ ถ้าของเก่าผิด ให้เขียนโน้ตใหม่ที่ลิงก์ถึงของเดิม
  แล้วแก้ของเดิมเป็น `status: superseded`
- ห้ามใส่ค่า secret (key, token, password) ในโน้ต — โน้ตถูก commit ลง git
  ให้บอกว่า secret อยู่ที่ไหน ไม่ใช่ค่าของมัน
```

## Template: โน้ตสามแบบที่ทำให้จำได้ข้ามค่าย

ทุกแบบเป็น Markdown ธรรมดา frontmatter เป็น YAML แบบที่ Obsidian อ่านได้ ไม่ใช่
รูปแบบที่มีแค่ Samong อ่าน ตอนนี้ Samong เก็บ frontmatter เป็นข้อความที่ค้นได้
ยังไม่ได้แยกเป็นข้อมูล ผลค้นจึงยังไม่ติดป้ายว่าโน้ตไหนถูกแทนแล้ว — agent ต้องอ่าน
บรรทัด `status` เอง ซึ่งบล็อกด้านบนสั่งไว้

**1. `START.md` — แผนที่ของ vault** อ่านก่อนอย่างอื่น สั้น และชี้ไปที่อื่น
ไม่ได้เก็บรายละเอียดเอง

```markdown
# START

โปรเจกต์นี้คืออะไร ใน 2–3 บรรทัด

- สถาปัตยกรรม: [[architecture]]
- ดีไซน์หน้าจอ: `docs/DESIGN.md`
- การตัดสินใจ: โฟลเดอร์ `decisions/`
- งานที่ค้าง: โฟลเดอร์ `handoff/`
- ศัพท์ของโดเมน: [[glossary]]
- วิธี deploy: [[runbooks/deploy]]
```

**2. `decisions/<เรื่อง>.md` — การตัดสินใจ** เขียนเมื่อเลือกทางใดทางหนึ่ง
ที่คนถัดไปอาจเลือกต่างออกไปถ้าไม่รู้เหตุผล

```markdown
---
status: active        # active | superseded
date: 2026-11-03
superseded_by:        # [[decisions/เรื่องที่มาแทน]] เมื่อถูกแทน
---
# ใช้ redb แทน sled

**บริบท** ตอนนั้นเจออะไร ทำไมต้องตัดสินใจ
**ทางเลือก** ที่พิจารณา และทำไมไม่เลือก
**ที่เลือก** และเหตุผล
**ห้ามพัง** สิ่งที่ต้องจริงเสมอ และเทสต์ที่ป้องกัน: `tests/phase10.rs`
**ไฟล์ที่เกี่ยว** `src/graph.rs`, `src/registry.rs`
```

ใส่ path ของไฟล์ไว้ในโน้ตเสมอ agent ที่กำลังจะแก้ `src/graph.rs` ค้นด้วย path นั้น
แล้วเจอโน้ตนี้ แม้จะไม่รู้ว่าเรื่องนี้ชื่ออะไร

**3. `handoff/<งาน>.md` — ส่งต่องานที่ยังไม่เสร็จ** เขียนทุกครั้งที่หยุดกลางทาง
โดยเฉพาะก่อนเปลี่ยนค่าย AI หรือก่อนสิทธิ์ใช้งานหมด

```markdown
---
status: active        # เปลี่ยนเป็น done เมื่อปิดงาน
date: 2026-11-03
branch: feature/report-export
---
# ส่งต่อ: export รายงานเป็น CSV

**เสร็จแล้ว** ...
**เหลือ** ...
**ขั้นต่อไป** คำสั่งหรือไฟล์แรกที่ต้องเปิด
**ลองแล้วไม่ได้ผล** อะไร และทำไม — ส่วนนี้คือส่วนที่หายไปก่อนเสมอ
**ต้องถามเจ้าของ** สิ่งที่ยังตัดสินเองไม่ได้
```

## Recipe: ให้หน้าจอใหม่ออกมาเหมือนหน้าเดิม

agent จำได้เฉพาะสิ่งที่ถูกเขียนลงไฟล์ ถ้าดีไซน์ของแอปอยู่แค่ในโค้ดกับความจำของคน
ทำ คำสั่งอย่าง "เพิ่มเมนูดูรายงานยอดขาย" ที่มาในอีกหนึ่งปีจะได้หน้าจอที่ทำงานถูก
แต่หน้าตาเป็นอีกแอปหนึ่ง — สีใหม่ ฟอนต์ใหม่ ผังใหม่ เพราะไม่มีอะไรบอกว่าของเดิม
เป็นแบบไหน

วิธีที่ใช้กับ Samong เอง และใช้กับโปรเจกต์ไหนก็ได้:

1. **เขียนดีไซน์ที่ทำไว้แล้วเป็นโน้ตหนึ่งไฟล์** เช่น `docs/DESIGN.md` อ่านจากโค้ด
   ไม่ใช่จากความตั้งใจ: สีแต่ละสีหมายถึงอะไร (ไม่ใช่แค่ค่า hex) token ทั้งสองธีม
   ฟอนต์และขนาด ผังหน้าจอ component ที่ใช้ซ้ำได้ตามชื่อ class และ**สูตรเพิ่มหน้าจอ
   ใหม่** — หน้าจอใหม่ส่วนใหญ่มีไม่กี่รูปทรง ให้เลือกรูปทรงก่อนลงมือ
   ตัวอย่างเต็มอยู่ที่ [`docs/DESIGN.md`](DESIGN.md) ของ repo นี้
2. **ผูกไว้ใน `AGENTS.md`** ให้ agent ทุกค่ายอ่านก่อนแตะ UI ทุกครั้ง แม้คำสั่งจะ
   พูดถึงแค่ process ของระบบ
3. **ให้เทสต์จับเมื่อเอกสารกับโค้ดไม่ตรงกัน** — เอกสารดีไซน์เป็นไฟล์ที่เลิกจริงได้
   เงียบๆ ที่สุด `tests/design_system.rs` เทียบตาราง token กับ stylesheet ทีละช่อง
   และห้ามเขียนสีนอก token block

เพราะเป็นไฟล์ `.md` ใน repo ถ้า vault ชี้ที่ project root มันก็อยู่ใน vault แล้ว
`search_notes("design system")` เจอมัน agent ตัวไหนก็ใช้ได้ และคนเปิดอ่านใน
เอดิเตอร์ได้โดยไม่ต้องมี Samong — การค้นด้วยคำเป็นการค้นคำตามตัว เอกสารภาษา
อังกฤษจึงไม่ขึ้นกับคำค้นภาษาไทย เว้นแต่จะเปิด semantic search ไว้

```markdown
## ก่อนแตะหน้าจอ

อ่าน `docs/DESIGN.md` ก่อนเสมอ — หน้าใหม่ เมนูใหม่ ปุ่มใหม่ หรือสีใหม่
คำสั่งที่พูดถึงแค่ process ("เพิ่มหน้าแสดงรายการ X") ก็ต้องได้หน้าจอตามเอกสารนี้
ห้ามสร้างสี ฟอนต์ ผัง ชุดไอคอน หรือ component library ที่เอกสารไม่มี
ถ้าจำเป็นต้องมีของใหม่จริง ให้เพิ่มลงเอกสารใน commit เดียวกัน
```
