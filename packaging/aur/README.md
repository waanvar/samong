# AUR — `samong-bin`

```sh
paru -S samong-bin      # or yay, or makepkg -si
```

Once the package is submitted to the AUR. Until then, build it from here:

```sh
cd packaging/aur
makepkg -si
```

## Why `-bin` and not a source package

Building Samong from source needs a Rust toolchain **and** Node, because the web UI
is compiled into the binary at build time. That is a lot to install in order to try
a note-taking tool, so this packages the published release archive and verifies it
against the SHA-256 released beside it.

A `samong` source package could exist later; it would have `makedepends=('rust'
'npm')` and take several minutes to build. `-bin` and source packages coexist
happily in the AUR, which is why this one declares `provides=('samong')` and
`conflicts=('samong')`.

## What is here

| | |
|---|---|
| `PKGBUILD` | the package |
| `.SRCINFO` | generated by `makepkg --printsrcinfo`; the AUR reads *this*, not the PKGBUILD |
| `generate.py` | rewrites `pkgver`, `_archive` and `sha256sums` for a new release |

`pkgver`, `_archive` and `sha256sums` move together and each mismatch fails
differently: a wrong `_archive` breaks `package()` *after* a successful download, a
wrong checksum fails before it, and a stale `pkgver` installs an old build under a
new version number. Hence the generator, and hence CI checking that the committed
PKGBUILD is what it produces.

`.SRCINFO` is what the AUR actually parses to show version and dependencies. A
PKGBUILD updated without regenerating it is the classic AUR mistake — the site keeps
advertising the old version. CI regenerates it in an Arch container and fails if the
committed copy differs.

## What CI verifies

On every push, inside an `archlinux` container:

- the committed PKGBUILD matches the generator, and `.SRCINFO` matches `makepkg --printsrcinfo`
- `makepkg` builds the package and the checksum matches
- `namcap` inspects both the PKGBUILD and the built package
- the package installs with `pacman -U`
- all four binaries run, a word inside a note is found, and a Thai sentence is
  segmented — the last one only works if the dictionary was compiled into the
  binary, so it is the assertion that catches a mis-built release

`options=('!strip' '!debug')` because these are prebuilt binaries: stripping a
shipped artefact makes it differ from the one whose checksum was published.

## Publishing

The AUR is its own git host and needs an AUR account with an SSH key registered.
That is not something this project's tooling holds, so the release workflow will push
only if an `AUR_SSH_KEY` secret exists, and otherwise says so and skips.

By hand, the first time:

```sh
git clone ssh://aur@aur.archlinux.org/samong-bin.git aur-samong-bin
cp packaging/aur/PKGBUILD packaging/aur/.SRCINFO aur-samong-bin/
cd aur-samong-bin
git add PKGBUILD .SRCINFO
git commit -m "samong-bin 0.3.9"
git push
```

Only `PKGBUILD` and `.SRCINFO` belong in the AUR repository — not this README, and
not the generator.
